*   **基础操作**：表的创建、字段定义（支持 int, float, string, bool, time 等类型）、单条/批量插入、单条/批量删除和更新。

### 2. 文档的缺失与不足（不完整的地方）

尽管涵盖了基础，但对于一个声称支持“全文检索”和“自定义匹配”的数据库，文档在以下关键领域存在信息断层：

#### A. 正则表达式支持的缺失（关键矛盾）
在之前的对话中，你提到文档支持正则，但在提供的文档文本中，**并没有找到关于 `regexp` 包或正则表达式（Regex）的具体 API 说明或代码示例**。
*   文档提到了 `Like` 操作符，但未明确其底层是简单的前缀匹配还是完整的正则匹配。
*   文档中关于“自定义匹配器”的示例仅展示了 `AgeGreaterThanMatcher`，缺乏如何在匹配器中集成正则的官方指导。

#### B. 全文检索（Full-Text Search）配置不详
文档虽然列出了创建全文索引的代码，但缺乏关键的**原理说明**和**配置参数**：
*   **分词器（Tokenizer）**：未说明使用的是什么分词算法（是单字分词、二元分词 ngram 还是词典分词）？是否支持中文分词？
*   **停用词（Stop Words）**：是否支持配置停用词表？
*   **模糊查询**：未说明全文检索是否支持模糊匹配、同义词或拼音检索。

#### C. API 接口文档化程度低
文档本质上是**“代码示例集”**而非**“API 手册”**：
*   **缺少函数签名**：大部分章节直接贴代码，缺乏对函数参数（Parameters）、返回值（Returns）和错误类型（Errors）的详细表格说明。
*   **缺少上下文**：例如 `storage.KVDb` 是如何初始化的？`engine.TableNew` 的底层依赖是什么？这些在文档中是隐式的。

#### D. 缺乏架构与限制说明
*   **数据规模限制**：未提及单表最大数据量、单字段最大长度限制（虽然之前推测是1000，但文档未明说）。
*   **并发模型**：未说明读写锁机制，多个 Goroutine 同时读写时的行为（是读写互斥还是支持并发读）。
