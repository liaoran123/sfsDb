# 第 2 章：核心概念与架构

在这一章中，我们将深入了解 sfsDb 的核心概念、整体架构设计以及各个包的职责。这将为后续章节的学习打下坚实的基础。

## 2.1 整体架构设计

sfsDb 采用"微内核"设计理念，整体架构清晰分层：

```
┌─────────────────────────────────────────────────────────┐
│                   应用层 (Application)                   │
├─────────────────────────────────────────────────────────┤
│              engine 包 (核心引擎)                      │
│  - 表管理 (Table)                                     │
│  - 索引管理 (Index)                                     │
│  - 查询引擎 (Search)                                    │
│  - 事务管理 (Transaction)                               │
├─────────────────────────────────────────────────────────┤
│              storage 包 (存储层)                       │
│  - LevelDB 封装                                         │
│  - 加密存储 (Encryption)                               │
│  - 配置管理 (Options)                                   │
├─────────────────────────────────────────────────────────┤
│              辅助包 (Utility Packages)                  │
│  - record (记录管理)                                    │
│  - time (时序数据)                                      │
│  - match (匹配器)                                       │
│  - util (工具函数)                                      │
│  - management (管理工具)                                │
│  - web (Web 界面)                                      │
└─────────────────────────────────────────────────────────┘
```

### 设计原则

1. **关注点分离**：每个包职责明确，互不干扰
2. **可扩展性**：易于添加新功能和优化
3. **高性能**：从架构层面考虑性能优化
4. **易用性**：API 设计简洁直观

## 2.2 包结构详解

### 2.2.1 engine 包（核心引擎）

**职责**：
- 表的创建、修改、删除
- 索引管理（主键、普通索引、全文索引）
- 数据查询（单条、范围、全文）
- 事务管理（无锁事务系统）

**核心文件**：
- `table.go` - 表的核心实现
- `index.go` - 索引实现
- `search.go` - 查询实现
- `insert.go` / `update.go` / `delete.go` - CRUD 操作
- `pools.go` - 对象池管理

**适用读者**：
- **初学者**：了解基本的表操作和查询 API
- **进阶开发者**：深入理解索引和查询优化
- **架构师**：研究无锁事务系统的实现

### 2.2.2 storage 包（存储层）

**职责**：
- LevelDB 存储引擎封装
- 加密存储功能
- 数据库配置管理
- 批量操作和快照

**核心文件**：
- `leveldb.go` - LevelDB 封装
- `encryption.go` - 加密存储实现
- `options.go` - 场景化配置

**适用读者**：
- **初学者**：了解如何打开和关闭数据库
- **进阶开发者**：学习加密存储和配置优化
- **架构师**：研究存储引擎的选型和封装

### 2.2.3 其他辅助包

#### record 包
- 记录的序列化和反序列化
- 对象池优化
- 内存管理

#### time 包

- 时序数据优化

- 监控统计

- 实时监控

## 2.3 数据模型

### 2.3.1 表结构

sfsDb 采用灵活的半结构化表设计：

```go
// 表结构示意
type Table struct {
    name   string
    fields map[string]FieldType
    indexs []Index
    // ...
}
```

**特点**：
- 默认包含自动增值的 `id` 字段
- 支持动态添加字段
- 字段类型灵活（通过 `any` 实现）

### 2.3.2 记录格式

每条记录在底层存储为键值对：
- **Key**：记录 ID
- **Value**：序列化的字段数据

## 2.4 存储引擎

### 2.4.1 LevelDB 基础

sfsDb 基于 goleveldb 构建，充分利用 LSM-Tree 架构的优势：

**LSM-Tree 优势**：
- 写入性能优异（顺序写入）
- 支持快照
- 压缩存储
- 跨平台兼容

### 2.4.2 存储层次

```
应用层 (engine)
    ↓
包装层 (EncryptedStoreWrapper - 可选)
    ↓
LevelDB 封装 (LevelDBStore)
    ↓
goleveldb
    ↓
磁盘存储
```

## 2.5 并发安全设计

### 2.5.1 无锁事务系统

采用乐观并发控制（OCC）机制：
- 避免传统锁机制的开销
- 支持高并发事务
- 在 10 并发下达到 26,315 ops/s

### 2.5.2 atomic.Value 的应用

在加密存储等场景中使用 `atomic.Value`：
- 读操作无锁
- 写操作原子
- 保证内存可见性

### 2.5.3 sync.Map 的使用

用于解密缓存等场景：
- 无需手动锁管理
- 适合读多写少
- 内置并发安全

## 2.6 对象池机制

### 2.6.1 为什么需要对象池

在高性能场景下，频繁的内存分配和垃圾回收会成为瓶颈：

**问题**：
- 小对象分配频繁
- GC 压力大
- 延迟不可预测

**解决方案**：
- 对象复用
- 减少 GC
- 提升性能

### 2.6.2 sfsDb 中的对象池

- `RecordPool` - 记录对象池
- `IterPool` - 迭代器对象池
- `BatchPool` - 批量操作对象池
- `AnyMapPool` - Map 对象池
