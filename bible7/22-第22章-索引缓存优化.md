## 19.1 完整的可运行示例

让我们通过一个完整的示例来演示 sfsDb 的索引缓存优化功能：

```go
package main

import (
	"fmt"
	"runtime"

	"github.com/liaoran123/sfsDb/engine"
	"github.com/liaoran123/sfsDb/storage"
)

func main() {
	fmt.Println("=== sfsDb 数据库实战 - 第 20 章：索引缓存优化示例 ===")
	fmt.Println()

	dbPath := "./bible_examples_chapter20_db"
	cleanup(dbPath)
	defer cleanup(dbPath)

	fmt.Println("1. 初始化数据库")
	_, err := storage.GetDBManager().OpenDB(dbPath)
	if err != nil {
		fmt.Printf("数据库打开失败: %v\n", err)
		return
	}
	defer storage.GetDBManager().CloseDB()
	fmt.Println("   ✓ 数据库打开成功")
	fmt.Println()

	fmt.Println("2. 创建表并设置字段")
	table, err := engine.TableNew("products")
	if err != nil {
		fmt.Printf("创建表失败: %v\n", err)
		return
	}

	fields := map[string]any{
		"id":       0,
		"name":     "",
		"category": "",
		"price":    0,
	}
	err = table.SetFields(fields)
	if err != nil {
		fmt.Printf("设置字段失败: %v\n", err)
		return
	}

	pk, _ := engine.DefaultPrimaryKeyNew("pk_id")
	pk.AddFields("id")
	table.CreateIndex(pk)

	nameIndex, _ := engine.DefaultNormalIndexNew("idx_name")
	nameIndex.AddFields("name")
	table.CreateIndex(nameIndex)

	categoryIndex, _ := engine.DefaultNormalIndexNew("idx_category")
	categoryIndex.AddFields("category")
	table.CreateIndex(categoryIndex)

	fmt.Println("   ✓ 表创建成功，包含 3 个索引")
	fmt.Println()

	fmt.Println("3. 插入测试数据（1000 条）")
	categories := []string{"图书", "电子产品", "服装", "食品", "家居"}
	for i := 1; i <= 1000; i++ {
		product := map[string]any{
			"id":       i,
			"name":     fmt.Sprintf("商品%d", i),
			"category": categories[i%5],
			"price":    i * 10,
		}
		_, err := table.Insert(&product)
		if err != nil {
			fmt.Printf("插入数据失败: %v\n", err)
			return
		}
	}
	fmt.Println("   ✓ 成功插入 1000 条商品数据")
	fmt.Println()

	fmt.Println("4. 根据系统内存设置索引缓存大小")
	var memStats runtime.MemStats
	runtime.ReadMemStats(&memStats)
	totalMemory := memStats.TotalAlloc / (1024 * 1024)
	
	fmt.Printf("   系统已分配内存: %d MB\n", totalMemory)
	
	if totalMemory > 1024 {
		fmt.Println("   内存充足，设置索引缓存为 3000")
		table.SetIndexCacheSizeLimit(3000)
	} else if totalMemory > 512 {
		fmt.Println("   内存适中，使用默认索引缓存 1000")
		table.SetIndexCacheSizeLimit(1000)
	} else {
		fmt.Println("   内存受限，设置索引缓存为 500")
		table.SetIndexCacheSizeLimit(500)
	}
	fmt.Println()

	fmt.Println("5. 测试索引缓存效果")
	fmt.Println("   执行多次相同查询，观察缓存效果：")
	
	for i := 0; i < 5; i++ {
		search := map[string]any{"category": "图书"}
		iter, _ := table.Search(&search)
		defer iter.Release()
		
		records := iter.GetRecords(true)
		defer records.Release()
		
		fmt.Printf("   第 %d 次查询：找到 %d 条记录\n", i+1, len(records))
	}
	fmt.Println("   ✓ 索引缓存测试完成")
	fmt.Println()

	fmt.Println("6. 查看索引缓存统计")
	stats := engine.GetIndexMatchCacheStats()
	fmt.Println("   索引缓存统计：")
	fmt.Printf("   - 缓存大小: %d\n", stats.Size)
	fmt.Printf("   - 访问次数: %d\n", stats.Accesses)
	fmt.Printf("   - 命中次数: %d\n", stats.Hits)
	fmt.Printf("   - 命中率: %.2f%%\n", stats.HitRate*100)
	fmt.Println()

	fmt.Println("7. 索引缓存最佳实践")
	fmt.Println("   - 根据系统配置调整缓存大小")
	fmt.Println("   - 根据数据量调整缓存大小")
	fmt.Println("   - 根据查询模式调整缓存大小")
	fmt.Println("   - 定期监控和调优")
	fmt.Println()

	fmt.Println("=== 索引缓存优化示例完成！===")
}

func cleanup(path string) {
	storage.GetDBManager().CloseDB()
}
```

## 19.2 索引缓存概述

索引缓存是 sfsDb 提供的另一个重要性能优化机制。它可以缓存索引计算结果，减少重复计算和磁盘访问，显著提高查询速度，特别是在处理大量数据时。

### 索引缓存的工作原理

1. **缓存索引计算结果**：当执行索引相关操作时，系统会将计算结果缓存起来
2. **缓存命中**：当再次执行相同的索引操作时，系统会直接使用缓存中的结果，避免重复计算
3. **缓存淘汰**：当缓存达到设定的大小限制时，系统会淘汰最久未使用的缓存项

---

## 19.3 SetIndexCacheSizeLimit 函数

`SetIndexCacheSizeLimit` 函数用于设置索引缓存的大小限制，控制内存使用并优化索引操作性能。

### 19.3.1 函数签名

**示例代码**（来自项目源码 `engine/table.go`）：

```go
// 设置索引缓存大小限制
func (t *Table) SetIndexCacheSizeLimit(limit int) {
    // 控制一个合理数值，防止缓存大小过大
    if limit <= 0 {
        limit = 1000
    }
    indexCacheSizeLimit = limit
}
```

---

### 19.3.2 参数说明

- `limit`: 索引缓存的最大数量
  - 当 `limit <= 0` 时，会使用默认值 1000
  - 当 `limit > 0` 时，会使用指定的值作为缓存大小上限

---

### 19.3.3 使用示例

```go
// 设置索引缓存大小为 2000
table.SetIndexCacheSizeLimit(2000)

// 设置索引缓存大小为默认值（1000）
table.SetIndexCacheSizeLimit(0) // 当值 ≤ 0 时，会使用默认值 1000
```

---

### 19.3.4 注意事项

- **默认值**：默认值为 1000，适用于大多数场景
- **内存使用**：较大的缓存大小可以提高频繁索引操作的性能，但会增加内存使用
- **性能权衡**：较小的缓存大小可以减少内存使用，但可能会降低频繁索引操作的性能
- **合理设置**：应根据系统内存情况和实际使用场景设置合适的缓存大小

---

## 19.4 索引缓存优化建议

### 19.4.1 根据系统配置调整

- **内存充足的系统**：可以适当增大缓存大小，如设置为 2000-5000
- **内存受限的系统**：应保持较小的缓存大小，如默认值 1000 或更小

---

### 19.4.2 根据数据量调整

- **大数据量场景**：适当增大缓存大小，以提高查询性能
- **小数据量场景**：保持默认缓存大小即可

---

### 19.4.3 根据查询模式调整

- **频繁重复查询**：增大缓存大小，以充分利用缓存效果
- **随机查询**：缓存效果有限，可以保持默认缓存大小

---

### 19.4.4 监控与调优

在实际使用中，应根据系统性能表现和内存使用情况，动态调整索引缓存大小：

1. **监控内存使用**：确保缓存大小不会导致系统内存不足
2. **监控查询性能**：观察缓存大小调整对查询性能的影响
3. **渐进式调整**：从小值开始，逐步增大，找到最佳平衡点

## 19.5 获取索引缓存统计

使用 `GetIndexMatchCacheStats()` 函数可以获取索引缓存的统计信息：

```go
stats := engine.GetIndexMatchCacheStats()
fmt.Printf("缓存大小: %d\n", stats.Size)
fmt.Printf("访问次数: %d\n", stats.Accesses)
fmt.Printf("命中次数: %d\n", stats.Hits)
fmt.Printf("命中率: %.2f%%\n", stats.HitRate*100)
```

**统计指标说明**：
- `Size`：当前缓存中的条目数量
- `Accesses`：缓存访问总次数
- `Hits`：缓存命中次数
- `HitRate`：缓存命中率（0.0 - 1.0）

## 19.6 性能测试

### 19.6.1 测试场景

### 19.6.2 测试结论

2. **缓存大小与内存使用正相关**：增大缓存大小会增加内存使用
3. **边际效应递减**：当缓存大小超过一定值后，性能提升会逐渐减少

## 19.7 最佳实践总结

1. **根据实际情况调整**：根据系统配置、数据量和查询模式设置合适的缓存大小
2. **避免过度缓存**：不要设置过大的缓存大小，以免占用过多内存
3. **定期监控**：定期监控系统性能和内存使用，及时调整缓存大小
4. **结合其他优化**：索引缓存优化应与其他优化措施（如索引设计、查询优化等）结合使用
