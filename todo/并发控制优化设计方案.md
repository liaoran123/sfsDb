# 并发控制优化设计方案

## 一、概述

### 1.1 项目背景

sfsDb是一个轻量级嵌入式关系型数据库，专注于提供高性能、灵活的存储解决方案。目前，sfsDb使用LevelDB的并发控制机制，但缺少细粒度的并发控制功能，如行级锁、乐观锁等，限制了数据库在高并发场景下的性能和可靠性。

### 1.2 设计目标

- 提供细粒度的并发控制，支持行级锁和乐观锁
- 实现死锁检测和预防机制
- 确保并发控制功能不会显著降低数据库性能
- 保持轻量级设计，资源占用低
- 提供简单易用的API接口，方便用户使用
- 与现有代码兼容，不破坏现有功能

## 二、功能需求

### 2.1 核心功能列表

| 功能点 | 描述 | 实现优先级 |
|--------|------|------------|
| 行级锁支持 | 支持对单个记录的读写锁定 | 高 |
| 乐观锁机制 | 支持基于版本号的乐观锁 | 高 |
| 死锁检测和预防 | 检测和预防死锁情况 | 中 |
| 细粒度并发控制 | 提供更细粒度的并发控制选项 | 中 |

### 2.2 详细功能描述

#### 2.2.1 行级锁支持

- **功能描述**：支持对单个记录的读写锁定，包括：
  - 共享锁（读锁）：多个事务可以同时获取读锁
  - 排他锁（写锁）：只允许一个事务获取写锁
  - 锁升级：支持从共享锁升级为排他锁

- **实现方式**：
  1. 维护一个锁表，记录每个记录的锁定状态
  2. 使用哈希表存储锁信息，支持快速查找
  3. 实现锁的获取、释放和升级逻辑

#### 2.2.2 乐观锁机制

- **功能描述**：支持基于版本号的乐观锁机制，包括：
  - 自动为记录添加版本号字段
  - 支持版本号的自动递增
  - 提供乐观锁冲突检测

- **实现方式**：
  1. 为每条记录添加版本号字段
  2. 读取记录时获取当前版本号
  3. 更新记录时检查版本号是否匹配
  4. 匹配成功则更新记录并递增版本号
  5. 匹配失败则返回冲突错误

#### 2.2.3 死锁检测和预防

- **功能描述**：检测和预防死锁情况，包括：
  - 死锁检测算法
  - 死锁预防策略
  - 死锁恢复机制

- **实现方式**：
  1. 实现等待图算法，检测死锁
  2. 实现超时机制，预防死锁
  3. 提供死锁恢复策略，如回滚优先级低的事务

#### 2.2.4 细粒度并发控制

- **功能描述**：提供更细粒度的并发控制选项，包括：
  - 可配置的锁超时时间
  - 可配置的死锁检测间隔
  - 支持不同的隔离级别

- **实现方式**：
  1. 提供配置选项，允许用户调整锁超时时间
  2. 提供配置选项，允许用户调整死锁检测间隔
  3. 支持不同的隔离级别，如读未提交、读已提交、可重复读

## 三、架构设计

### 3.1 整体架构

并发控制优化功能将作为sfsDb的一个模块，位于`engine层`，与现有表、索引模块协同工作。

```
┌─────────────────┐
│    API层        │ ← 提供并发控制相关API
└─────────────────┘
        ▲
        │
┌─────────────────┐
│    engine层     │
│  ┌───────────┐  │
│  │ 并发控制模块 │  │ ← 新增模块
│  └───────────┘  │
│  ┌───────────┐  │
│  │ 表模块     │  │ ← 集成并发控制功能
│  └───────────┘  │
│  ┌───────────┐  │
│  │ 索引模块   │  │ ← 集成并发控制功能
│  └───────────┘  │
└─────────────────┘
        ▲
        │
┌─────────────────┐
│    storage层    │ ← 存储锁信息和版本号
└─────────────────┘
```

### 3.2 模块划分

并发控制模块将划分为以下子模块：

1. **锁管理器**：负责锁的获取、释放和管理
2. **乐观锁管理器**：负责乐观锁的版本号管理和冲突检测
3. **死锁检测器**：负责死锁的检测和预防
4. **事务管理器**：负责事务的创建、提交和回滚
5. **API模块**：负责提供并发控制相关的API接口
6. **配置模块**：负责管理并发控制功能的配置

## 六、性能优化

### 6.1 锁管理器优化

- **锁表优化**：使用高效的哈希表实现锁表，支持快速查找
- **读写锁分离**：使用读写锁保护锁表，支持并发读操作
- **锁超时机制**：设置合理的锁超时时间，避免长时间等待

### 6.2 乐观锁优化

- **版本号存储优化**：将版本号存储在记录中，避免额外的存储开销
- **批量操作支持**：支持批量更新操作的乐观锁处理
- **冲突检测优化**：使用高效的版本号比较算法

### 6.3 死锁检测优化

- **增量检测**：只检测可能发生死锁的事务
- **定期检测**：根据配置的间隔定期检测死锁，避免频繁检测
- **高效算法**：使用等待图算法，高效检测死锁

### 6.4 事务管理优化

- **事务池**：复用事务对象，减少内存分配
- **批量提交**：支持批量提交事务，减少I/O开销
- **异步提交**：支持异步提交事务，提高并发性能
