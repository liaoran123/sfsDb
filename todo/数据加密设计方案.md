# sfsDb 数据加密设计方案

## 一、概述

根据功能分析，sfsDb目前没有数据加密相关的实现。本设计方案旨在为sfsDb添加数据加密功能，保护用户数据的安全性。

## 二、设计目标

1. **安全性**：使用强加密算法保护数据
2. **性能**：最小化加密对数据库性能的影响
3. **易用性**：提供简单的API接口，方便用户使用
4. **兼容性**：与现有代码兼容，不破坏现有功能
5. **灵活性**：支持多种加密配置和密钥管理方式

## 三、加密架构设计

### 3.1 加密层次

在sfsDb的架构中，加密功能将实现在**storage层**，具体来说：

- **位置**：在`storage`包中，作为`Store`接口的增强实现
- **透明性**：对上层（engine层和API层）透明，不需要修改现有代码
- **可插拔**：支持启用/禁用加密功能

## 四、核心设计

### 4.1 加密算法选择

- **主算法**：AES-256-GCM
  - 原因：安全强度高，支持认证加密，性能优秀
  - 用途：加密数据块，同时提供完整性验证

- **密钥派生**：PBKDF2-HMAC-SHA256
  - 原因：适合从密码派生密钥，安全性高
  - 用途：当用户提供密码而非直接密钥时使用

### 4.2 密钥管理

#### 4.2.1 密钥类型
 
1. **主密钥（Master Key）**：
   - 用于加密数据库中的所有数据
   - 长度：256位
   - 存储：由用户管理，或使用密钥管理服务

2. **数据加密密钥（DEK）**：
   - 可选，用于加密不同的数据分区
   - 长度：256位
   - 存储：使用主密钥加密后存储在数据库中

#### 4.2.2 密钥提供方式

1. **直接提供密钥**：
   - 用户在打开数据库时直接提供主密钥
   - 适合有自己密钥管理系统的用户

2. **密码派生密钥**：
   - 用户提供密码，系统使用PBKDF2派生密钥
   - 适合简单使用场景

3. **外部密钥管理**：
   - 支持从外部密钥管理服务获取密钥
   - 适合企业级应用

### 4.3 加密范围

1. **数据加密**：
   - 加密所有存储在磁盘上的数据
   - 包括表数据、索引、元数据

2. **不加密的内容**：
   - 数据库结构信息（如字段名、表名，可选择加密）
   - 索引结构（索引值会被加密）

### 4.4 性能优化

1. **可选加密**：
   - 允许用户选择是否启用加密
   - 允许用户选择加密的表或字段

2. **缓存优化**：
   - 缓存解密后的数据，减少重复解密操作
   - 合理设置缓存大小，平衡内存使用和性能

3. **批量操作**：
   - 支持批量加密/解密操作，减少开销

## 五、API设计

## 六、实现细节

### 6.1 加密包装器

在`storage`层实现一个加密包装器，包装现有的存储实现：

```go
// EncryptedStoreWrapper 加密存储包装器
type EncryptedStoreWrapper struct {
    // 底层存储
    underlyingStore Store
    
    // 加密配置
    config *EncryptionConfig
    
    // 加密器
    encryptor Encryptor
    
    // 解密缓存
    decryptionCache map[string][]byte
    
    // 缓存互斥锁
    cacheMutex sync.RWMutex
}
```

### 6.2 加密器接口

```go
// Encryptor 加密器接口
type Encryptor interface {
    // 加密数据
    Encrypt(plaintext []byte) ([]byte, error)
    
    // 解密数据
    Decrypt(ciphertext []byte) ([]byte, error)
    
    // 获取加密算法
    Algorithm() string
}

// 实现AES-256-GCM加密器
type AESGCMEncryptor struct {
    key []byte
    algorithm string
}
```

### 6.3 核心方法实现

```go
// Put 加密存储数据
func (es *EncryptedStoreWrapper) Put(key, value []byte) error {
    // 加密值
    encryptedValue, err := es.encryptor.Encrypt(value)
    if err != nil {
        return err
    }
    
    // 存储加密后的数据
    return es.underlyingStore.Put(key, encryptedValue)
}

// Get 获取并解密数据
func (es *EncryptedStoreWrapper) Get(key []byte) ([]byte, error) {
    // 从缓存获取
    cacheKey := string(key)
    es.cacheMutex.RLock()
    if value, ok := es.decryptionCache[cacheKey]; ok {
        es.cacheMutex.RUnlock()
        return value, nil
    }
    es.cacheMutex.RUnlock()
    
    // 从底层存储获取加密数据
    encryptedValue, err := es.underlyingStore.Get(key)
    if err != nil {
        return nil, err
    }
    
    // 解密数据
    value, err := es.encryptor.Decrypt(encryptedValue)
    if err != nil {
        return nil, err
    }
    
    // 存入缓存
    es.cacheMutex.Lock()
    es.decryptionCache[cacheKey] = value
    es.cacheMutex.Unlock()
    
    return value, nil
}
```

## 七、密钥管理

### 7.1 密钥生成

1. **直接密钥**：
   - 由用户提供，长度必须为256位
   - 建议使用密码学安全的随机数生成器生成

2. **密码派生**：
   ```go
   // 使用PBKDF2派生密钥
   func DeriveKey(password, salt []byte, iterations int) ([]byte, error) {
       return pbkdf2.Key([]byte(password), salt, iterations, 32, sha256.New)
   }
   ```

### 7.2 密钥轮换

支持密钥轮换功能，允许用户更换加密密钥：

```go
// ReEncrypt 重新加密所有数据
func (es *EncryptedStoreWrapper) ReEncrypt(newKey []byte) error {
    // 创建新的加密器
    newEncryptor, err := NewAESGCMEncryptor(newKey)
    if err != nil {
        return err
    }
    
    // 遍历所有数据
    iter := es.underlyingStore.Iterator(nil, nil)
    defer iter.Release()
    
    // 使用事务批量处理
    batch := es.underlyingStore.GetBatch()
    defer batch.Reset()
    
    for iter.First(); iter.Valid(); iter.Next() {
        key := iter.Key()
        encryptedValue := iter.Value()
        
        // 解密旧数据
        plaintext, err := es.encryptor.Decrypt(encryptedValue)
        if err != nil {
            return err
        }
        
        // 使用新密钥加密
        newEncryptedValue, err := newEncryptor.Encrypt(plaintext)
        if err != nil {
            return err
        }
        
        // 更新批次
        batch.Put(key, newEncryptedValue)
    }
    
    // 提交批次
    if err := es.underlyingStore.WriteBatch(batch); err != nil {
        return err
    }
    
    // 更新加密器
    es.encryptor = newEncryptor
    es.config.MasterKey = newKey
    
    // 清空缓存
    es.cacheMutex.Lock()
    es.decryptionCache = make(map[string][]byte)
    es.cacheMutex.Unlock()
    
    return nil
}
```

## 八、性能考虑

1. **加密开销**：
   - AES-256-GCM的加密解密速度很快，对性能影响较小
   - 预计加密会增加约5-15%的CPU开销
   - 存储开销会增加约16字节/条（认证标签）

2. **缓存策略**：
   - 实现LRU缓存，缓存最近使用的解密数据
   - 缓存大小可配置，默认1000条记录
   - 定期清理过期缓存项

3. **批量操作优化**：
   - 对批量操作进行优化，减少加密解密次数
   - 支持批量加密/解密API

## 九、迁移策略

1. **现有数据库迁移**：
   - 提供工具将未加密数据库迁移到加密数据库
   - 迁移过程：
     - 打开未加密数据库
     - 创建加密数据库
     - 遍历所有数据，加密后写入新数据库
     - 验证数据完整性

2. **平滑升级**：
   - 加密功能设计为可选，不影响现有代码
   - 现有数据库可以继续使用，无需立即加密

## 十、安全考虑

1. **密钥安全**：
   - 密钥不在内存中明文存储（可选择）
   - 支持密钥在使用后立即清除
   - 建议用户使用安全的密钥管理方案

2. **防止暴力破解**：
   - 使用足够的PBKDF2迭代次数（默认100,000次）
   - 支持配置迭代次数

3. **防止侧信道攻击**：
   - 使用常数时间比较函数
   - 避免密钥处理中的 timing 泄漏

4. **审计日志**：
   - 可选的审计日志功能，记录加密相关操作
   - 支持配置日志级别
