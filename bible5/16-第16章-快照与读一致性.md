## 17.1 完整的可运行示例

让我们通过一个完整的示例来演示 sfsDb 的快照与读一致性功能：

```go
package main

import (
	"fmt"
	"os"
	"time"

	"github.com/liaoran123/sfsDb/engine"
	"github.com/liaoran123/sfsDb/storage"
)

func main() {
	fmt.Println("=== sfsDb 数据库实战 - 第 9 章：快照与读一致性示例 ===")
	fmt.Println()

	dbPath := "./bible_examples_chapter09_db"
	cleanup(dbPath)
	defer cleanup(dbPath)

	fmt.Println("1. 初始化数据库")
	_, err := storage.GetDBManager().OpenDB(dbPath)
	if err != nil {
		fmt.Printf("数据库打开失败: %v\n", err)
		return
	}
	defer storage.GetDBManager().CloseDB()
	db := storage.KVDb
	fmt.Println("   ✓ 数据库打开成功")
	fmt.Println()

	fmt.Println("2. 创建表并设置字段")
	table, err := engine.TableNew("products")
	if err != nil {
		fmt.Printf("创建表失败: %v\n", err)
		return
	}
	table.kvStore = db

	fields := map[string]any{
		"id":    0,
		"name":  "",
		"price": 0,
	}
	err = table.SetFields(fields)
	if err != nil {
		fmt.Printf("设置字段失败: %v\n", err)
		return
	}

	pk, _ := engine.DefaultPrimaryKeyNew("pk_id")
	pk.AddFields("id")
	table.CreateIndex(pk)
	fmt.Println("   ✓ 表创建成功")
	fmt.Println()

	fmt.Println("3. 插入初始数据")
	products := []map[string]any{
		{"id": 1, "name": "产品 A", "price": 100},
		{"id": 2, "name": "产品 B", "price": 200},
		{"id": 3, "name": "产品 C", "price": 300},
	}

	for _, p := range products {
		_, err = table.Insert(&p)
		if err != nil {
			fmt.Printf("插入数据失败: %v\n", err)
			return
		}
	}
	fmt.Println("   ✓ 成功插入", len(products), "条产品数据")
	fmt.Println()

	fmt.Println("4. 创建快照")
	snapshot, err := db.Snapshot()
	if err != nil {
		fmt.Printf("创建快照失败: %v\n", err)
		return
	}
	defer snapshot.Release()
	fmt.Println("   ✓ 快照创建成功（时间点 S1）")
	fmt.Println()

	fmt.Println("5. 修改数据库（在快照之后）")
	updateProduct := map[string]any{"id": 1, "name": "产品 A (已更新)", "price": 150}
	table.Update(&updateProduct)

	newProduct := map[string]any{"id": 4, "name": "产品 D", "price": 400}
	table.Insert(&newProduct)

	table.Delete(&map[string]any{"id": 3})
	fmt.Println("   ✓ 数据库修改完成：")
	fmt.Println("   - 更新产品 1")
	fmt.Println("   - 新增产品 4")
	fmt.Println("   - 删除产品 3")
	fmt.Println()

	fmt.Println("6. 从当前数据库读取（修改后的数据）")
	iterDB, _ := table.Search(&map[string]any{"id": nil})
	defer iterDB.Release()
	recordsDB := iterDB.GetRecords(true)
	defer recordsDB.Release()
	fmt.Println("   当前数据库记录：")
	for _, r := range recordsDB {
		fmt.Printf("   - %v\n", r)
	}
	fmt.Println()

	fmt.Println("7. 从快照读取（原始数据，保持一致性）")
	snapshotIter := snapshot.Iterator(nil, nil)
	defer snapshotIter.Release()

	fmt.Println("   快照数据（S1 时刻）：")
	snapshotSearch := func(start, limit []byte) storage.Iterator {
		return snapshot.Iterator(start, limit)
	}

	rangeIter, _ := table.SearchRange(snapshotSearch, "id", 1, 3)
	defer rangeIter.Release()
	snapshotRecords := rangeIter.GetRecords(true)
	defer snapshotRecords.Release()

	for _, r := range snapshotRecords {
		fmt.Printf("   - %v\n", r)
	}
	fmt.Println()

	fmt.Println("8. 验证快照不包含新增的产品 4")
	checkID4 := func() bool {
		testIter, _ := table.SearchRange(snapshotSearch, "id", 4, 4)
		defer testIter.Release()
		recs := testIter.GetRecords(true)
		defer recs.Release()
		return len(recs) == 0
	}
	if checkID4() {
		fmt.Println("   ✓ 验证通过：快照中不包含产品 4")
	} else {
		fmt.Println("   ✗ 验证失败：快照中包含了产品 4")
	}
	fmt.Println()

	fmt.Println("9. 工业物联网场景：使用快照生成设备状态报告")
	fmt.Println("   模拟场景：")
	fmt.Println("   - 设备数据持续变化")
	fmt.Println("   - 需要生成某一时刻的完整状态报告")
	fmt.Println("   - 使用快照确保报告数据的一致性")
	fmt.Println()

	fmt.Println("=== 快照与读一致性示例完成！===")
}

func cleanup(path string) {
	os.RemoveAll(path)
}
```

这段代码展示了 sfsDb 的完整快照与读一致性功能：

1. **初始化数据库**：通过 `storage.GetDBManager().OpenDB()` 打开数据库
2. **创建表**：使用 `engine.TableNew()` 创建表
3. **插入数据**：使用 `Insert()` 插入初始数据
4. **创建快照**：使用 `db.Snapshot()` 创建时间点 S1 的快照
5. **修改数据**：在快照创建后修改、新增、删除数据
6. **读取当前数据**：从数据库读取修改后的数据
7. **读取快照数据**：从快照读取 S1 时刻的原始数据
8. **验证一致性**：确认快照不包含后续新增的数据
9. **场景演示**：工业物联网中使用快照生成一致的状态报告

## 17.2 快照概述

快照是 sfsDb 提供的一种高级功能，用于创建数据库在某个时间点的一致性读视图。通过使用快照，您可以在数据持续变化的环境中，获取到数据库在快照创建时刻的完整、一致的数据状态。

### 17.2.1 快照的特点

- **读一致性**：快照提供数据库在创建时刻的一致性视图，不受后续数据修改的影响
- **无阻塞**：创建快照不会阻塞数据库的写操作
- **高效**：快照是轻量级的，创建和使用成本低
- **隔离性**：快照读取与数据库的其他操作完全隔离

### 17.2.2 快照与事务的区别

| 特性 | 快照 | 事务 |
|------|------|------|
| 主要用途 | 提供一致性读视图 | 确保操作的原子性、一致性、隔离性和持久性 |
| 写操作支持 | 仅支持读操作 | 支持读写操作 |
| 性能开销 | 低 | 高 |
| 实现方式 | 基于存储引擎的快照机制 | 基于锁或MVCC机制 |
| 适用场景 | 读多写少的场景，如报表生成、数据备份 | 对数据一致性要求高的场景，如金融交易 |

## 17.3 使用快照

### 17.3.1 创建快照

```go
// 创建快照
snapshot, err := db.Snapshot()
if err != nil {
    panic(err)
}
defer snapshot.Release() // 确保释放快照资源
```

### 17.3.2 从快照读取数据

```go
// 从快照读取单个键值
value, err := snapshot.Get([]byte("key"))
if err != nil {
    panic(err)
}
fmt.Printf("Value: %s\n", value)

// 使用快照迭代器遍历数据
iter := snapshot.Iterator(nil, nil)
defer iter.Release()

for iter.Next() {
    key := iter.Key()
    val := iter.Value()
    fmt.Printf("Key: %s, Value: %s\n", key, val)
}
```

### 17.3.3 释放快照

快照使用完毕后，必须释放其资源：

```go
// 释放快照资源
err := snapshot.Release()
if err != nil {
    panic(err)
}
```

## 17.4 读一致性示例

### 17.4.1 基本读一致性示例

```go
// 创建数据库
db, err := storage.NewLevelDBStore("./test_db", nil)
if err != nil {
    panic(err)
}
defer db.Close()

// 写入初始数据
db.Put([]byte("key1"), []byte("value1"))
db.Put([]byte("key2"), []byte("value2"))

// 创建快照
snapshot, err := db.Snapshot()
if err != nil {
    panic(err)
}
defer snapshot.Release()

// 修改数据
db.Put([]byte("key1"), []byte("new_value1"))
db.Put([]byte("key2"), []byte("new_value2"))

// 从数据库读取（获取到修改后的数据）
dbValue1, _ := db.Get([]byte("key1"))
dbValue2, _ := db.Get([]byte("key2"))
fmt.Printf("From DB: key1=%s, key2=%s\n", dbValue1, dbValue2)

// 从快照读取（获取到修改前的数据，保持一致性）
snapshotValue1, _ := snapshot.Get([]byte("key1"))
snapshotValue2, _ := snapshot.Get([]byte("key2"))
fmt.Printf("From Snapshot: key1=%s, key2=%s\n", snapshotValue1, snapshotValue2)

// 输出结果：
// From DB: key1=new_value1, key2=new_value2
// From Snapshot: key1=value1, key2=value2
```

## 17.5 快照的应用场景

### 17.5.1 工业边缘计算

- **设备状态监控**：使用快照获取某个时间点的所有设备状态，确保监控数据的一致性
- **生产数据分析**：基于快照生成生产报表，避免数据在分析过程中发生变化
- **故障诊断**：在设备出现故障时，使用快照保存故障发生时的完整数据状态，便于后续分析

### 17.5.2 物联网场景

- **传感器数据聚合**：使用快照聚合多个传感器在同一时间点的数据
- **设备配置管理**：确保读取到设备的完整配置信息，不受配置更新的影响
- **数据同步**：在边缘设备与云端同步数据时，使用快照确保同步数据的一致性

### 17.5.3 其他场景

- **数据备份**：基于快照进行增量备份，避免备份过程中数据发生变化
- **报表生成**：生成财务报表、业务分析报表等需要数据一致性的场景
- **测试环境**：在测试过程中使用快照，确保测试数据的一致性和可重复性

## 17.6 性能考量

### 17.6.1 快照的开销

- **创建开销**：快照创建操作非常轻量，几乎不影响数据库性能
- **存储开销**：快照共享底层存储，不会额外占用存储空间
- **读取开销**：从快照读取数据的性能与从数据库直接读取相近

### 17.6.2 最佳实践

- **及时释放**：快照使用完毕后应立即释放，避免占用资源
- **合理使用**：仅在需要一致性读视图的场景中使用快照
- **批量操作**：对于需要读取大量数据的场景，使用快照可以减少数据不一致的风险
- **避免嵌套**：不支持从快照创建快照，应避免尝试这种操作

---

## 17.7 注意事项

1. **只读操作**：快照仅支持读操作，不支持写操作
2. **资源管理**：必须调用 `Release()` 方法释放快照资源，否则可能导致资源泄漏
3. **快照生命周期**：快照的生命周期应尽可能短，仅在需要时创建，使用完毕后立即释放
4. **嵌套限制**：不支持从快照创建快照，尝试这样做会返回错误
5. **存储引擎依赖**：快照功能依赖于底层存储引擎的快照支持，目前仅 LevelDB 存储引擎支持此功能
